Use `qwen/qwen3-30b-a3b-instruct-2507` through OpenRouter, restricted to
`siliconflow/fp8`, with provider fallback disabled. This dated, compact instruction
model is a reasonable low-cost starting candidate for text classification. Its
quality on this job is unmeasured. The binary labels are placeholders until the
job's label definitions and error costs are known.

## Configuration contract

`decision-model.json` is an application configuration template, not a complete
classifier implementation. Send only its rendered `request_template` as the API
request body; use the environment variable named in `transport.api_key_env` for
Bearer authentication. Substitute the rubric and input using JSON serialization.
Reject unresolved placeholders and enforce all local policy fields in the caller.

The proposed decision bands are calibrated probability <= 0.10 for negative,
>= 0.90 for positive, and human review otherwise. Raw model scores must never be
compared directly to these thresholds. Abstentions, malformed or truncated
responses, API failures, and missing or unvalidated calibration go to review.
Validate the response schema and finite numeric range locally too. Do not replace
an unavailable endpoint with another model or provider without revalidation.

## Confirm thresholds before release

1. **Define success.** Replace the placeholder labels with a versioned rubric and
   labeled examples. Establish the relative costs of false positives, false
   negatives, and review, plus review capacity. The config's 98% precision/negative
   predictive value and 60% automation coverage are illustrative proposed gates,
   not established requirements. Confirm suitable targets before treating them as
   release criteria.
2. **Build independent splits.** Use adjudicated, representative production-like
   examples, preserving expected class prevalence. Split by entity and time where
   needed to prevent duplicate or customer leakage. Separate prompt development,
   calibration fitting, threshold selection, and a locked final test. Include
   ambiguous inputs, missing information, embedded instructions, and important
   language/customer slices. Use rare-case stress tests in addition to the
   prevalence-matched test; do not mix their metrics without weighting.
3. **Collect and calibrate.** Run the exact pinned request, rubric, and provider.
   Save raw scores, abstentions, failures, true labels, latency, token usage, and
   returned model/provider metadata. Fit Platt scaling on the calibration split
   only. Check reliability plots and Brier score on independent data. A score of
   0.9 generated by the model does not establish 90% correctness. If scores do not
   separate classes, improve the rubric or change the candidate and rerun.
4. **Select two thresholds.** Sweep lower/upper threshold pairs on the selection
   split using calibrated scores. Start with 0.10/0.90, then choose the pair that
   meets the agreed error constraints and review capacity. Measure precision among
   auto-positive cases, negative predictive value among auto-negative cases,
   false-positive/false-negative rates, automation coverage, and review workload.
   Count abstentions and failures in total workload and coverage denominators;
   report reviewed cases separately rather than assuming they are correct.
5. **Test once, with uncertainty.** Freeze the prompt, calibrator, and thresholds,
   then evaluate the locked test. Require one-sided 95% exact binomial lower
   confidence bounds to exceed the configured quality gates for each automated
   class. Zero predicted cases cannot pass. Check critical slices with enough
   labeled examples, accounting for multiple comparisons if making simultaneous
   claims. Inspect confusion counts as well as aggregate metrics, review load,
   p95 latency, and cost. If the test fails, revise using development data and
   obtain a new untouched test before making another release claim.
6. **Publish the evidence and stage release.** Store the rubric, calibration
   artifact and hash, chosen thresholds, dataset/split versions, and evaluation
   report alongside this model/provider pin. Only then mark the configuration
   validated. Shadow production traffic first, followed by a small canary with
   sampled human labels. Monitor class mix, score drift, audited error rates,
   coverage, latency, and spend; send decisions to review when gates fail. Any
   model, provider, rubric, or calibration change requires revalidation.
